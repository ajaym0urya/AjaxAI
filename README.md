# AjaxAI

> **An Autonomous AI Operating System powered by collaborative agent swarms that continuously plans, reasons, learns, and executes work across the web and enterprise systems.**

AjaxAI is a production-ready SaaS platform built using Microsoft technologies for the **Microsoft AI Hackathon**. Rather than short-lived, chat-based prompts, AjaxAI operates around long-running, self-healing **Objectives** designed to orchestrate agent workflows asynchronously over days or weeks.

---

## Architecture Overview

AjaxAI uses a monorepo structure separating frontend, API layer, and background agent workloads:

```
AjaxAI/
├── apps/
│   ├── frontend/             # Next.js 15 Command Center Dashboard
│   └── chrome-extension/     # manifest V3 Clipper extension
├── services/
│   ├── backend/              # Express API Server (SignalR WebSocket gateway)
│   └── agent-runtime/        # Agent Swarm execution loops & tool registry
├── packages/
│   └── shared/               # Shared models, DB Client, and Seed script
├── infra/                    # Azure Bicep & Deployment automation
├── docker-compose.yml        # Multi-service container launcher
└── package.json              # Monorepo workspaces definition
```

### The 12-Agent Swarm

1. **Chief Orchestrator Agent**: Controls schedule, task execution pipelines, and escalates blockers.
2. **Planner Agent**: Performs goal decomposition and builds dynamic roadmaps.
3. **Research Agent**: Collects and indexes content from the web using searches.
4. **Browser Agent**: Headless browser controller using Playwright scripts.
5. **Memory Agent**: Performs long-term vector embeddings search and retrieves episodic history.
6. **Knowledge Agent**: Extracts semantic relations and builds the Knowledge Graph.
7. **Validator Agent**: Audits outputs to evaluate confidence scores and reduce hallucination.
8. **Security Agent**: Enforces RBAC permissions and blocks sensitive actions until approved.
9. **Recovery Agent**: Runs self-healing routines, handles errors, and plans retries.
10. **Reflection Agent**: Refines planning strategies through reinforcement metrics.
11. **Opportunity Agent**: Detects high-relevance job openings, events, and certifications.
12. **Communication Agent**: Formats reports and executes outward messaging triggers.

## Database Schema (Cosmos DB)

The application utilizes the following collections (defined in `@ajaxai/shared`):
* `users`: User profiles, roles, and authorization scopes.
* `objectives`: User-defined objectives, status machine milestones, and dependencies.
* `tasks`: Dynamic roadmap tasks generated by the Planner Agent.
* `subtasks`: Granular checklist points to track step-by-step progress.
* `agentRuns` & `agentMessages`: Execution audits and conversation channels between agents.
* `memories`: Vector-embedded context records (Episodic, Semantic, Procedural, Org).
* `opportunities`: AI-scored certifications, jobs, and competitor activity.
* `approvals`: Human-in-the-loop gates for payments, external messages, and forms.
* `knowledgeNodes` & `knowledgeEdges`: Node-edge structure mapping for the interactive graph.
* `notifications`: Real-time notifications and approval triggers.

## Getting Started (Local Development)

The codebase has zero initial configuration overhead for local evaluation, falling back to a local `db.json` database if Azure credentials are not yet provisioned.

### Prerequisites

* Node.js v20+
* NPM Workspaces support

### Installation & Seeding

1. Clone the repository and install all dependencies:
   ```bash
   npm run install:all
   ```

2. Seed the database with sample profiles, objectives, tasks, and knowledge items:
   ```bash
   npm run seed
   ```

3. Spin up all services concurrently (Frontend, Backend, and Agent Runtime):
   ```bash
   npm run dev
   ```

* **Frontend Console**: [http://localhost:3000](http://localhost:3000)
* **Backend API Gateway**: [http://localhost:3001](http://localhost:3001)
* **WebSocket / SignalR Endpoint**: `ws://localhost:3001/signalr`

## Cloud Deployment (Azure)

The platform now ships with a GitHub Actions pipeline that builds the workspace and deploys the Azure foundation from [infra/main.bicep](infra/main.bicep) on every push to `main`.

1. Create these GitHub secrets in the repository:
   - `AZURE_CLIENT_ID`
   - `AZURE_TENANT_ID`
   - `AZURE_SUBSCRIPTION_ID`
   - `AZURE_COSMOS_CONNECTION_STRING`
   - `AZURE_OPENAI_API_KEY`
   - `AZURE_OPENAI_ENDPOINT`
   - `AZURE_OPENAI_DEPLOYMENT_NAME`
   - `AZURE_WEB_PUBSUB_CONNECTION_STRING`
   - `AZURE_AI_DOC_INTEL_ENDPOINT`
   - `AZURE_AI_DOC_INTEL_KEY`
   - `OUTLOOK_CONNECTION_STRING`

2. Push to `main` or run the `AjaxAI Azure CI/CD` workflow manually.

3. The workflow first deploys the Azure foundation with Bicep, then builds the frontend, Python backend, and agent runtime images, and finally updates the Azure Container Apps revisions automatically.

The Bicep template provisions the core shared services: Azure Container Registry, Log Analytics, Container Apps environment, Cosmos DB, Key Vault, and Service Bus. The backend reads its deployment URL from `FRONTEND_URL`, and the frontend reads its API base from `NEXT_PUBLIC_API_BASE` plus `NEXT_PUBLIC_WS_BASE` during the image build. That keeps Azure and local development aligned while still allowing the app to run against the local `db.json` fallback when Cosmos DB is not configured.
